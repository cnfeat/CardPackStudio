使用说明

01每天一张，每张 5 分钟。拿出今天的卡片，认真读完问题，写下你真实的第一反应。不要修饰，不要敷衍。
02诚实比正确重要。这不是考试，没有人打分。如果你连自己都骗，这套卡片帮不了你。
03可以反复使用。三个月后再翻同一张卡，你的答案变了——说明你在进步。答案不变，说明你该警惕了。
04跟团队一起用。拿出几张关键决策卡，扔到团队会议里。看每个人怎么写，再讨论。你会发现信息差远比想象的大。
05把答案归档。回头翻看你六个月前、一年前的决策记录，那是最好的成长日记。

CHAPTER 01
机会发现
所有的创业都始于一个念头。但这个念头是真实的机会，还是你脑补出来的伪需求？先学会分辨，再谈出发。

卡 001 - 030
机会发现001 / 300
001
你发现的这个「机会」，是用户真正的痛点，还是你脑补出来的伪需求？
你能不能找到一个真实的人，说出他因为这个痛点而痛苦的具体时刻？如果找不到，你的机会可能只存在于你的 PPT 里。「我身边很多人都需要」和「我验证过有人愿意为此付费」之间，隔着多少次真实对话？
机会发现002 / 300
002
这个问题有多痛？用户现在是怎么忍受它的？
用户现在用的替代方案是什么？是 Excel、是手动、是干脆不做？「忍一忍就过去了」和「不解决就活不下去」，是完全不同量级的机会。你的目标用户，现在为了绕开这个问题，付出了多少时间、金钱或情绪？
机会发现003 / 300
003
你凭什么认为这个机会是你的？别人为什么没做？
如果这个痛点这么明显、市场这么大，为什么聪明人没有蜂拥而入？是因为他们没看见，还是看见了但发现做不成？你比别人多知道的那一点，到底是什么？是信息差、技术差，还是纯粹的一厢情愿？
机会发现004 / 300
004
这个需求是「应该有」还是「必须有」？
用户说「这个功能不错」和「没有它我活不下去」，你听到的是同一个意思吗？「应该有」是锦上添花，「必须有」是雪中送炭。你的产品，卖的是哪种？当预算紧张时，用户会先砍掉哪一类产品？
机会发现005 / 300
005
你是在追风口，还是在解决问题？
把你想法里所有的流行词（AI、Web3、元宇宙、出海）都去掉，剩下的那个问题还成立吗？如果答案是「不成立」，那你在追的就不是机会，是情绪。风口会过去，问题会留下来——你押注的是哪一个？
机会发现006 / 300
006
这个机会的天花板在哪里？你能算出市场有多大吗？
「市场很大」是一句空话。你能说出目标用户的数量级吗？是十万、百万还是千万？你能说出他们每年在这个问题上花多少钱吗？如果你连市场规模的上下限都估不出来，你凭什么判断值不值得做？
机会发现007 / 300
007
谁是你的第一个用户？他叫什么名字？
如果你说不出第一个愿意付费的用户具体是谁，说明你还没有真正接触过市场。一个具体的人，比一万个抽象的「目标用户画像」都更有价值。你能在今天之内，找到并联系上这个「第一个用户」吗？
机会发现008 / 300
008
你为什么是现在做，而不是三年前，或者三年后？
为什么时机是现在？是技术刚成熟、成本刚降下来，还是政策刚放开、用户习惯刚养成？如果三年前做太早、三年后做太晚，那「现在」的窗口期，你凭什么判断它真的开着？
机会发现009 / 300
009
这个机会的可验证性有多高？
你的核心假设，能不能用最低成本的方式快速证伪？「用户会喜欢」不是一个可验证的假设，「用户会在 30 天内为它付费」才是。你愿不愿意在投入大资源之前，先设计一个能打脸的实验？
机会发现010 / 300
010
你愿意为验证这个想法付出什么代价？
如果这个想法最后证明是错的，你能接受失去什么？时间、金钱、还是面子？那些不肯为验证付出任何代价的人，最后往往在市场上付出了更大的代价。你的止损线画在哪里？
机会发现011 / 300
011
如果这个想法失败了，最可能的原因是什么？
现在就预演失败：是需求不存在、是执行太差、是竞争太强，还是钱烧完了？如果你能提前说出最可能的死法，你就知道自己该优先补哪一块短板。你创业路上最大的那颗雷，埋在哪里？
机会发现012 / 300
012
你是在解决自己的问题，还是别人的问题？
很多创始人都是「自己的第一个用户」。但如果你不是目标用户，你对问题的理解就隔了一层。「我痛过」是优势，「我以为他们痛」是幻觉。你现在的这个需求，是你亲身痛过，还是听来的？
机会发现013 / 300
013
这个痛点的频次有多高？是每天、每月，还是一生一次？
高频痛点才有复购和粘性，低频痛点只能做一锤子买卖。你的用户多久会遇到一次这个问题？如果是「一生一次」的婚礼、买房，你靠什么养活一个持续运营的生意？
机会发现014 / 300
014
用户为了这个问题，已经花了多少钱或多少时间？
花钱和时间，是衡量痛点强度的最硬指标。如果用户现在分文未花、只是口头抱怨，那说明问题还没痛到要解决的地步。用户现有的「土办法」，成本是多少？你的方案能把这个成本降下来吗？
机会发现015 / 300
015
有没有人已经在用「土办法」解决这个问题？
如果你的用户已经在用 Excel、微信群、纸笔、甚至雇了个兼职在解决这个问题，那反而是好事——说明需求真实存在。你的机会，是把这些「土办法」产品化。你现在要替代的，是用户哪个「土办法」？
机会发现016 / 300
016
你的机会是基于技术红利，还是基于需求洞察？
技术红利会消失，需求洞察会沉淀。如果支撑你机会的是「AI 现在能做这个了」，那 AI 能力再强一点，或者竞争对手也用上 AI，你的优势还在吗？需求侧的变化，才是更持久的护城河。
机会发现017 / 300
017
三年后这个机会还存在吗？
如果三年后这个需求消失了，你的创业就只是一场短跑。政策会变、技术会迭代、用户的习惯会迁移。你的机会是结构性的长期趋势，还是一次性的短期窗口？你愿意为「三年后还在」付出什么？
机会发现018 / 300
018
你是在找「好做的」，还是「值得做的」？
「好做」的事，往往因为门槛低，早就挤满了人。「值得做」的事，往往因为难，反而留出了空白。你现在盯上的机会，是因为它简单而选它，还是因为它的价值足够大，大到值得你啃下那些硬骨头？
机会发现019 / 300
019
这个市场是在增长，还是在萎缩？
在增长的市场里，即使你做得很平庸，也可能被大潮带着往前走。在萎缩的市场里，即使你是最优秀的，也可能逆水行舟。你所处的这个市场，是涨潮还是退潮？你能拿出什么数据来证明？
机会发现020 / 300
020
你观察到的机会，有多少是「幸存者偏差」？
你看到的成功案例，只是活下来的那部分。那些死在半路的创业者，你看见了吗？当一个赛道看起来「大家都在赚钱」时，很可能只是死掉的人你没看见。你凭什么认为，自己会站在幸存者那一侧？
机会发现021 / 300
021
你的直觉和你的数据打架时，你信谁？
很多伟大的机会，最初都违背当时的「数据共识」。但更多的失败，也是死于忽视数据。你怎么区分「天才的直觉」和「愚蠢的执念」？你现在对这个机会的判断，有多少来自真实的观察，多少来自自我说服？
机会发现022 / 300
022
如果只能选一个用户痛点来解决，你会砍掉哪些？
创业初期最大的错误，是想一次性解决所有问题。如果让你从现在的方案里砍掉 80% 的功能，只留最核心的那一个痛点，你会留哪个？你的用户愿意为这「一个」痛点买单吗？
机会发现023 / 300
023
这个机会的护城河在哪里？
如果你一上线，巨头或者更聪明的团队明天就来抄，你挡得住吗？你的护城河是数据、网络效应、品牌，还是你独特的认知？如果答案是「他们懒得抄」，那你要担心的不是竞争，是这个机会本身可能太小。
机会发现024 / 300
024
你是不是在用「新概念」包装一个「旧需求」？
把「知识付费」说成「认知升级」，把「团购」说成「社交电商」，需求本身并没有变。真正的创新，是解决了新的问题，而不是给旧问题换个新名字。你的机会，经得起把包装拆掉后的审视吗？
机会发现025 / 300
025
这个需求是显性的，还是隐性的？
显性需求人人看得见，早就被做烂了。隐性需求藏在用户的抱怨、勉强和将就里，用户自己都未必说得清。你要解决的需求，用户能自己说出口吗？还是需要你去观察、去翻译他们没说出口的那部分？
机会发现026 / 300
026
你验证过这个想法吗，还是只在脑子里跑过一遍？
「我觉得行」和「市场告诉我行」之间，隔着无数次真实的接触。你最近一次和潜在用户面对面聊这个想法，是什么时候？他们听完后的第一反应是什么——是追问细节，还是礼貌地点头？
机会发现027 / 300
027
你是在复制别人的成功，还是找到了别人没看见的东西？
「某某在美国做成了，我在中国抄一个」是路径，不是洞察。复制的红利在于执行，洞察的红利在于认知。你现在的机会，如果纯粹是复制，你凭什么比原版和本地已有的竞品做得更好？
机会发现028 / 300
028
机会的窗口期有多长？你能在窗口关闭前跑多远？
窗口期是「别人还没反应过来」到「市场已经饱和」之间的时间。你有多少时间？半年还是一年？以你现在的资源和人手，你能在窗口期内完成验证、做出产品、跑通模型吗？如果不能，你该加速，还是该换一个窗口更长的机会？
机会发现029 / 300
029
如果今天必须放弃这个想法，你最舍不得的是什么？
认真想想这个问题。你舍不得的是它真实的价值，还是你已经投入的沉没成本？「舍不得」里藏着的，往往是你对这个机会最诚实的判断。那个让你死抓着不放的东西，到底值多少钱？
工具 · 框架030 / 300
030
机会三问：痛点 · 方案 · 市场
一个念头能不能成为创业机会，用三层过滤。任何一层不通过，都该回头重新审视。
1痛点验证：这个问题真实存在吗？有多痛？频次多高？用户现在怎么解决？
2方案验证：你的方案真的能解决它吗？比现有「土办法」好多少？好到用户愿意换？
3市场验证：有足够多的人愿意为此付费吗？付费意愿能支撑起一个可持续的生意吗？
三层验证按顺序推进，不要跳过。一个不痛的痛点，配再好的方案也是伪需求；一个没有付费意愿的市场，配再痛的需求也是公益。

市场与用户031 / 300
031
你的目标用户，用一句话说清楚是谁？
不能说「所有人」「中小企业」「年轻人」——这些都是偷懒的答案。试着精确到：某个城市、某个职业、某个年龄段、正在经历某个具体困境的人。你的答案越具体，说明你越了解市场；越笼统，说明你越是在拍脑袋。
市场与用户032 / 300
032
你在为「买得起的人」设计，还是在为「用得到的人」设计？
买单的人和使用的人，可能是两拨人。给企业做培训软件，用的是员工，买的是老板。你了解的是哪一个？如果你的产品使用者和付费者不是同一个人，你分别满足他们各自的什么诉求？
市场与用户033 / 300
033
你的用户画像里，有几个是你真的聊过的人？
用户画像是从真实的人里提炼的，不是坐在办公室里编出来的。你最近一个月，和多少个真实的目标用户深度聊过？如果这个数字是零，你画像里的一切都只是你的想象。
市场与用户034 / 300
034
你的市场，是大众市场还是利基市场？
大众市场大而分散，获客贵、竞争烈；利基市场小而集中，容易切入但天花板低。你现在的选择是什么？一个足够小的利基市场，能不能成为你撬动更大市场的支点？
市场与用户035 / 300
035
你的 TAM、SAM、SOM 分别是多少？
TAM（总市场）、SAM（可服务市场）、SOM（可获取市场）——这三个数字你算过吗？很多创始人张口就是 TAM 几百亿，却连 SOM 都说不清。你第一年能切到的那块蛋糕，到底有多大？
市场与用户036 / 300
036
用户的痛点，是他「说出来」的，还是你「看出来」的？
用户说出来的往往是愿望，不是痛点。「我想要更快的马」背后，真正的需求是「更快到达」。你有没有观察过用户的真实行为，而不是只听他们怎么说？行为，永远比语言诚实。
市场与用户037 / 300
037
你的用户现在在哪里聚集？
他们混哪个社区、看哪个博主、参加哪个社群、用哪个工具？如果你不知道去哪找你的用户，你的获客成本就会高到可怕。你现在能具体说出三个「用户聚集地」吗？
市场与用户038 / 300
038
谁是你「不想服务」的用户？
知道不服务谁，和知道服务谁一样重要。如果来了一个用户，需求明显跑偏，你敢不敢拒绝？敢拒绝，说明你有清晰的定位；来者不拒，说明你的产品会很快变成一锅乱炖。
市场与用户039 / 300
039
你了解用户的一天吗？
从起床到睡觉，你的目标用户一天是怎么过的？在哪个时间点、什么场景下，他会遇到你解决的那个问题？如果你描绘不出用户的一天，你做的产品就很难嵌入他的生活。
市场与用户040 / 300
040
用户的决策链有多长？谁是最终的拍板人？
B 端产品尤其如此：采购、审批、使用、付款，可能是四个人。你了解这条决策链上的每一环吗？谁发起、谁评估、谁拍板、谁买单？你只搞定了使用的人，能不能搞定付钱的人？
市场与用户041 / 300
041
你的用户为什么「现在」还没解决这个问题？
是不知道有方案，还是觉得太贵，还是不相信别人，还是懒得折腾？搞清楚「现在还没解决」的原因，比搞清楚「问题本身」更重要，因为它直接决定了你的切入点。你卡在用户不行动的哪个环节上？
市场与用户042 / 300
042
早期用户里，谁是最愿意尝鲜的那批人？
不是所有人都愿意用新产品。真正会先试用的，是那些被痛点折磨得最深、或者天生爱尝鲜的人。你能识别出这批「创新者」和「早期采用者」吗？你的第一批用户，打算从哪个群体里挖？
市场与用户043 / 300
043
你做过用户访谈吗？还是只发过问卷？
问卷能告诉你「什么」，访谈才能告诉你「为什么」。你有没有坐在一个真实用户对面，听他讲他完整的故事，追问到「为什么」的第三层？你最近一次深度访谈，挖出了什么问卷里从没出现过的东西？
市场与用户044 / 300
044
用户嘴上说的，和钱包投票的，一致吗？
「我觉得这个挺好」和「我愿意付 99 块」之间，隔着一条鸿沟。你有没有测过用户的真实付费意愿？有多少人嘴上说要，最后真掏钱的？这个落差，就是理想和现实的差距。
市场与用户045 / 300
045
你的产品是卖给「个人」还是「组织」？
2C 和 2B 是两套完全不同的逻辑：决策速度、付费周期、获客方式、客户关系，全都不同。你清楚自己站在哪一边吗？还是想「两头通吃」，结果两头都不讨好？
市场与用户046 / 300

Mom Test：别让妈妈骗了你
一套避免「用户碍于情面说好话」的访谈方法，核心是只问过去的事实，不问对未来的看法。
1问过去，不问未来：「你上次是怎么解决这个问题的」，而不是「你会用我的产品吗」。
2问细节，不问感受：「为了这个花了多少钱、多少时间」，而不是「你觉得这个怎么样」。
3聊问题，不聊方案：先确认痛点存在，再提你的方案，否则用户会顺着你的话说。
4盯行为，不听承诺：用户说「会买」不算数，只有掏钱或付出行动才算数。
核心口诀：凡是「我会…」「我可能…」的回答都要打折；凡是「我上次…」「我花了…」的回答都要深挖。

Kano 模型：功能的优先级排序
不是所有功能都值得做。用 Kano 模型区分功能的类型，把资源花在刀刃上。
1必备型：没有它用户会暴怒，但有了也不会更满意（登录、支付）。——及格线，做好即可。
2期望型：做得越好用户越满意，越差越不满意（速度、稳定性）。——持续投入的重点。
3魅力型：有了是惊喜，没有也不失望（彩蛋、智能推荐）。——差异化来源，但要控制数量。
4无差异型：做不做用户都无感。——坚决砍掉，别浪费资源。
先补必备型，再投入期望型，用魅力型制造惊喜，砍掉无差异型。别把资源浪费在用户根本不在乎的功能上。

Build-Measure-Learn 循环
精益创业的核心闭环：不是「做完了就赢」，而是「每循环一次就更懂一点」。
1Build 构建：用最小的成本，做出一个能验证假设的最小版本（MVP）。
2Measure 度量：收集真实的行为数据，而不是用户嘴上说的话。
3Learn 学习：从数据里得出结论——假设成立、推翻、还是需要调整。
4Pivot / Persevere 转向或坚持：基于学习，决定继续、转向，还是放弃。
循环越快，学得越快。创业不是一次冲刺，而是无数次「构建—度量—学习」的快速旋转。慢的循环，是最大的隐性成本。

不同阶段，融的钱、证明的事、面临的考核都不一样。认清自己在哪个阶段，别用错姿势。

单位经济学：LTV / CAC
判断生意能不能持续的两个核心数字，一个算「能赚多少」，一个算「花多少换来」。
1LTV 客户终身价值：一个客户从来到走，总共贡献的利润。
2CAC 获客成本：获取一个新客户，平均要花多少钱。
3黄金比例：LTV / CAC 大于 3，才是健康的生意。
4回收期：花出去的获客成本，多久能赚回来（越短越好）。
LTV/CAC 小于 1，说明每获取一个客户都在亏钱，规模越大亏越多。先把这个比例做正，再谈增长。
